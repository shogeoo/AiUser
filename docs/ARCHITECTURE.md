# Архитектура

Проект — автономный агент, который держит постоянное подключение к Telegram через Telethon
и общается с LLM через OpenAI-совместимый API (по умолчанию OpenRouter). LLM не выполняет код:
она возвращает JSON-действия, а рантайм исполняет их и возвращает результаты обратно в контекст.

## Поток данных

```
Telegram update
   │ Telethon events.Raw
   ▼
assistant._raw_handler ──► events.serialize_event ──► EventBuffer (debounce)
                                                            │ по таймеру
                                                            ▼
                              context.add_user_message (по одному сообщению на событие)
                                                            │
                                                            ▼
                                          assistant._request_actions
                                       (OpenAI chat.completions + json_schema)
                                                            │
                                                {"actions": [...]}
                                                            ▼
                                            executor.execute_actions
                                        (выполнение по порядку, один поток)
                                                            │
                          ┌─────────────────────────────────┼───────────────────────────┐
                          ▼                                 ▼                           ▼
                 high-level команда                  raw TL-запрос              docsearch / docfetch
                 (Telethon client)               (telethon.tl.functions.*)      (индекс API)
                          │                                 │                           │
                          └─────────────────────────────────┼───────────────────────────┘
                                                            ▼
                                     action_result (по одному сообщению на действие)
                                                            │
                                                            ▼
                                     context.add_user_message (хронологически)
                                                            │
                                                            └──► следующий вызов модели,
                                                                 пока actions не пуст
```

## Модули

| Файл | Ответственность |
| --- | --- |
| `main.py` | точка входа, настройка логирования, запуск асинхронного цикла |
| `src/config.py` | переменные окружения, пути, `MODEL_NAME`, `EVENT_BUFFER_TIMEOUT` |
| `src/logger.py` | консольный цветной логгер и файлы `logs/` |
| `src/model_info.py` | запрос `/models` у OpenRouter и определение input-модальностей модели |
| `src/schema.py` | JSON-схема ответа модели (`{"actions": [...]}`) |
| `src/commands.py` | whitelist high-level команд Telethon |
| `src/dto.py` | сериализация Telegram DTO в JSON и обратная сборка TL-объектов |
| `src/events.py` | обёртка сериализации входящего update |
| `src/api_docs.py` | ленивый индекс Telegram API, `docsearch` и `docfetch` |
| `src/executor.py` | выполнение действий, `action_result`, обработка ошибок, вложения медиа |
| `src/buffer.py` | debounce-буфер событий: копит обновления и отдаёт пачкой |
| `src/context.py` | история сообщений и её персистентность в `context.json` |
| `src/assistant.py` | агентный цикл, сквозные id действий, хронологический сброс очереди |
| `src/exceptions.py` | иерархия ошибок выполнения действий |

## Ключевые решения

- **Без tool calling.** Модель возвращает единый объект `{"actions": [...]}`; результаты передаются
  обычными user-сообщениями, а не tool-протоколом.
- **Строгий structured output.** `response_format: json_schema` гарантирует форму ответа; содержимое
  вложенных DTO валидируется рантаймом (см. `docs/PROTOCOL.md`).
- **Полный DTO без сокращений.** События и результаты не теряют поля; байты кодируются как `$bytes`,
  даты — ISO-строками.
- **Хронология.** События и результаты действий идут отдельными сообщениями и сливаются по внутреннему
  счётчику порядка (`assistant._flush_pending`), чтобы модель видела реальную последовательность.
- **Entity-like значения.** Для `InputPeer`/`InputUser`/`InputChannel` модель передаёт скаляры
  (id / marked id / username), а Telethon сам вызывает `get_input_entity` внутри `request.resolve`.
- **Сквозные id.** Рантайм присваивает действиям последовательные `a000001`, `a000002`, ... и
  восстанавливает счётчик из `context.json` при старте.

## Поток управления в агенте

`TelegramAIAssistant._agent_turn`:

1. сбрасывает накопленные события и результаты в контекст отдельными сообщениями;
2. запрашивает у модели действия;
3. если действий нет — завершает ход (или продолжает, если пришли новые события во время запроса);
4. выполняет действия по порядку; каждое готовое действие сразу публикует `action_result`, который
   попадёт в контекст на следующей итерации;
5. повторяет цикл.

## Ограничения архитектуры

- Приём звонков не реализован: нужен DH-обмен и медиаслой.
- Нет ограничений на число итераций, паузы и размер вложений.
- Контекст не обрезается автоматически.
